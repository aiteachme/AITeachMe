## 对建议的判断

建议有道理，尤其是把外部协议升级与内部运行统一分开、复用 P0—P2、先验证字段完整往返再开放混合题型。`llm()` 可以统一模型依赖，但平台仍须负责字段合同、版本、渲染、提交验证、评分证据和训练语义。新题型无需改代码的前提，是采用平台已经实现的文本表单与评分能力。

原建议中的阶段应视为工作包，不是要求完全串行：统一选择协议需提前设计，测试应随实现建立；真实模型质量仍是独立发布门禁。

## 验证依据

最终相关后端回归：233 项通过；前端 Node 测试：107 项通过；`npm run build` 通过；`git diff --check` 通过。后端仅报告既有 TestClient/httpx 弃用提示，前端构建仍有大块产物体积提示。这里的 233 项是本轮选择的相关回归集合，不代表后端全库测试。

- 后端覆盖包校验/安装/下载、动态生成约束、V1 多字段兼容、各类型配额与补题、评分证据、版本停用后历史重放、答案隐藏、提交/幂等、画像隔离、`.atmx` 同步和工作流元数据。
- 四字段、两字段及 V1 的答辩/面试/辩论，使用固定模型返回值检查生成 → 冻结字段 → 评分；动态模型拒绝未知字段与缺少必填字段。
- 混合卷测试令内置题得 1/1、自定义题得 0/99，确认长期掌握度仍为 1，课程/用户画像只读取可纳入画像的题目。
- 前端 Node 测试覆盖配置迁移、多种自定义题混选、字段重排、草稿 JSON 往返、空答案识别与空白导出清理；生产构建验证生成后的 API 类型。
- Playwright 使用真实生产组件和隔离固定数据检查测验表单、字段恢复、考卷回看与空白打印、闯关评分失败后重试和完成；这不是连接真实服务与模型的全站端到端测试。
- 使用项目打印样式输出 A4 PDF，经 Poppler 渲染检查，两页完整显示六个字段；空白打印的六个字段值均为空。截图和 PDF 位于工作区 `output/playwright/`。

可复现的重点测试文件：`backend/tests/test_question_type_package_v2.py`、`test_question_type_package_installation.py`、`test_export_import_workflow_contracts.py`、`test_profile_reliability.py`；`frontend/tests/custom-question-fields.test.mjs`、`training-config.test.mjs`。

## 发布前仍需验证

P4 应使用独立人工课程案例评估真实模型的出题质量与 strong/partial/wrong 判分，记录时延、成本和失败率；再执行部署环境的完整训练路径和移动端回归。本轮没有把固定模型测试或包格式校验当成教学效果证明，也没有进行生产部署。
