## 本地仍有的主要阻塞

### 新课程规划超时

使用 conda `atm` 的 Python、隔离数据目录运行 FastAPI 9020 和 Vite 5180，关闭启动时 OpenAPI/Orval 自动生成。

两次新课程实测分别得到：

| 路径 | 结果 |
| --- | --- |
| 默认规划模型 `gpt-6-luna` | 约 73.51 秒返回 502，`LLM_CALL_ERROR`；后端异常链为 `httpx.ReadTimeout` |
| 显式选择 `reason`，实际为 `gpt-6-sol` | 约 75.74 秒返回相同 502；后端异常链同样为 `httpx.ReadTimeout` |

两条路径的资料上传、解析、伴读和历史保存均成功。伴读首个正文 token 分别约 9.38 秒、10.91 秒，没有 SSE 错误事件。

规划失败后没有知识单元，后续考试请求返回 `409 NO_KNOWLEDGE_UNITS_FOR_EXAM`。这是建课未完成的后续阻塞，不能据此认定考试模块本身故障；这两轮没有执行到新的讲义和图谱生成。

为独立验证下游功能，另用新临时身份上传已有课程包，恢复真实知识单元和讲义，再实际生成新试卷：1 道单选约 49.42 秒进入 ready，提交后 graded，画像同步 completed，更新 2 个状态、2 个复习任务；掌握度、学习计划和复习列表都读取成功。该结果不能替代新建课全流程验收。

目前可确定的是本地规划的模型流读取超时；不能仅凭异常类型断定网络、网关和具体流式响应处理中的哪一层是根因。下一步应针对同一规划请求检查上游输出与连接终止情况。本轮没有修改生产模型、用户配置、重试策略或超时值。
