本文记录统一前的验收结果（四个 V1 示例、两个 V2 示例）。后续六包统一为 V2 的改动及新增验证单独记录在 [题型统一记录](question-type-unification-20260929.md)，旧验收结果没有重新标记为新包测试结果。

## 结论与验收范围

**P4 网页版实现与功能验收已完成。** 六个示例题型在测验、考卷、一次性闯关中均完成真实生成和评分，共 18 条题型/模式路径。后端相关回归 441 项、前端 108 项及生产构建通过。现有 V1/V2 包继续使用同一执行链路，没有新增另一套题型系统。

用户已明确：参考常规题目，由大模型自动生成与评分，不需要人工介入；当前只需网页版实现。此前将教师确认、API 实际费率和桌面/云端部署列为阻塞项，超出了本轮要求，现撤销这些前置条件。本次验收覆盖浏览器功能及本地生产构建，不代表已向外部服务器发布。

模型质量记录保留：96 个样例中 95 个满足预设分数区间，96 个及格判断全部符合预期；曾生成一处错误的参考答案均值，增强指导后三题复查通过。独立课程案例由代理编写并交给生产模型评分，未将其标注为人工审核。上述结果用于持续自动评估，不新增人工审批流程。

## 本轮复现并修复的问题

| 问题 | 原因与改动 | 验证 |
| --- | --- | --- |
| 结构化模型调用每次先异常 | 当前 Instructor 的整数重试路径试图把 `httpx.Timeout` 转为浮点数，在实际请求前失败，随后走修复路径 | 使用一次尝试的 `AsyncRetrying`，保留现有 helper 的总超时和重试；显式声明 tenacity 依赖。真实 Instructor + 模拟传输回归先失败后通过 |
| 证据不匹配时重复同一错误 | 模型拼接或改写引文，服务端严格校验拒绝；第二次请求没有收到校验原因 | 重试仅加入服务端校验的短诊断及逐字引用要求，不传递供应商异常。仍最多两次，证据不合法仍拒绝计分；新增回归通过，真实评分重试通过 |
| 单题评分失败变成泛化 500 | 工作流失败未转换为单题接口的业务错误 | 返回 502 和“本次评分未完成，请重试。未产生有效成绩。”；`QUESTION_TEMPLATE_GRADE_FAILED`，更新 OpenAPI 并重新生成客户端 |
| PDF 在自定义作答框中间分页 | 字段容器沿用网格且缺少字段级分页约束 | 打印时改为块布局，单字段避免内部断页，题干/标签尽量与后文同页；重新输出并查看全部页面 |
| 闯关完成仍残留断网提示 | 已开始的轮次仍在重连时后台 prepare，错误状态在完成后继续展示 | 活跃轮次停止重新 prepare；加载/错误只在尚未建轮次时显示。生产构建实测断网、恢复、完成及重开 |
| 已成功生成的试卷可能释放额度 | 即时结算只接受 ready/completed；多进程下另一请求先将试卷推进到 submitted、grading 等状态时会释放，和恢复结算不一致 | 两条路径共用 `EXAM_GENERATION_COMPLETED_STATUSES`；真实额度表回归在修复前有 6 项失败，修复后全部通过，重放不重复扣费 |

另外调整生成指导：面向学生使用字段中文标签；复核总和、样本数、均值和单位；不能仅凭均值推断统计显著。这是质量改进，不能宣称已解决所有算术错误。

验收脚本也纠正了两处计量问题：重放交卷请求的耗时不再当作原始评分时长；继续质量评估时保留之前的 token 记录。对已完成 96 项的评估执行无新模型调用的恢复检查，72 条用量记录完整保留。

## 评分与出题质量

### 评分样例

调用生产评分器、冻结真实包定义，使用既有共享调度器；没有模拟模型返回。六个包各有三个包内案例，另加每包一个独立编写的课程案例。每个案例包含 strong、partial、wrong、blank 四种回答。

| 来源 | 样例数 | 满足预设分数区间和及格判断 |
| --- | --- | --- |
| 包内案例 | 72 | 71 |
| 代理独立编写的保留案例 | 24 | 24 |
| 合计 | 96 | 95（98.96%） |

96/96 及格判断符合预期；24/24 空白为零分且不调用模型。其余 72 个样例产生 72 次真实调用，无供应商请求失败。评估结果及逐条证据见 [quality-results.json](../../backend/tmp/p4-20260929/quality-results.json)。

唯一区间偏差：费曼包 `newton-second-law/partial`，回答“牛顿第二定律是 F=ma，力越大加速度越大。”，期望 0.30–0.59，实际 0.255。模型确认公式，但缺少合力、质量、举例及惯性系边界；加权分为 `0.45×0.40 + 0.30×0.25 = 0.255`。两者均低于及格线 0.60。保留原预期、rubric 和实际结果作为后续自动评估的偏差样本，实际作答继续由现有模型流程自动判分。

独立案例见 [training_quality_independent.json](../../backend/tests/fixtures/training_quality_independent.json)。其“正确 ≥0.80、错误 ≤0.20、部分正确低于及格线”是自动评估的预设检查口径，不要求人工课程审批。一次测评也不代表多次采样、跨模型、跨课程都稳定。

### 已发现的参考答案错误

首次测验案例中，B 组数据为 `18,19,20,20,21,22,23,80`。正确均值为 `223/8=27.875`，参考答案却写成 `25.0`。结构合同全部合法，参考答案往返仍可得满分，因此必须将“链路通过”与“内容正确”分开验收。

该历史快照保留，没有直接改库掩盖问题。[原始问题记录](../../backend/tmp/p4-20260929/generation-initial-review.json)。增强指导后又真实生成三道不同案例，独立重算总和、均值和排除极端值后的数值均正确，题干也未出现内部字段 key；[复查记录](../../backend/tmp/p4-20260929/generation-followup-review.json)。**三题复查不足以证明通用数值可靠性**；当前按与常规题一致的自动流程运行，数值可靠性继续作为自动质量评估项目。

## 复现入口

以下在 `backend` 目录执行。真实模型阶段会产生网关用量；`--data-dir` 必须是 `backend/tmp` 下的新专用目录，setup 不覆盖已有数据库。

```powershell
# 1. 新建隔离课程与模型配置副本
python scripts/run_training_acceptance.py setup --data-dir tmp/p4-new

# 2. 单独终端启动隔离 API，保持运行
python scripts/run_training_acceptance.py serve --data-dir tmp/p4-new --port 9031

# 3. 导入六包、三模式生成，然后真实评分
python scripts/run_training_acceptance.py generate --data-dir tmp/p4-new --port 9031
python scripts/run_training_acceptance.py submit --data-dir tmp/p4-new --port 9031

# 4. 96 项评分质量检查，可在同一目录继续未完成的样例
python scripts/evaluate_training_quality.py --data-dir tmp/p4-new
```

修改包或样例后应使用新的验收目录，避免复用旧案例结果。版本兼容脚本为 `scripts/check_training_compatibility.py --data-dir ... --paper-id ...`，输入必须是隔离 paper_exam 课程中**另备的 ready 试卷**；它会升级/停用题型、交空卷并恢复目录版本。本次使用 paper 4，不能再次对已评分的 paper 4 执行。

## 本轮收口

1. 自定义题型沿用常规题目的 LLM 自动生成/判分方式，保留结构、证据、权重和历史快照校验，不增加教师确认步骤。
