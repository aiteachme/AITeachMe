# DocGen 修复流程收敛与验收（2026-10-22）

## 交付规则

修复步骤直接产出完成纠错的内容。修复后不再启动另一个模型复审，也不将已知未修复的错误伪装成成功。

本次处理三个流程根因：

- 原来每次错误补丁之后再调用独立模型复审，意见分歧或审核调用异常会拒收补丁并反复重试。现由修复器在输出前完成复算，程序负责原位替换、范围、题数、题型和题答协议；有效修复直接应用。
- 原来整本审核服务不可用，会创建 `record_only + error` 的“审核未完成”动作，后面没有实现能够执行它，最终必然阻断发布。现保留实际规则检查结果并记录服务异常，不将服务异常当成已经发现的正文错误。
- 原来部分章节错误使用仅记录、重派发或重建骨架标签，没有真正进入内容修复。现有明确目标章节的错误统一执行实际修复；审核提示词也要求直接输出能执行的局部修复动作。临时调用异常、空修补与无效结构在同一目标内接受具体反馈并有限重试，其它目标已经完成的修改保留。

大题组仍按题号进行结构化替换，其余题目逐字保留。原文定位、数量、题型、答案折叠、发布原子性及错误没有修复时不能冒充完成的检查继续保留。没有新增交付状态、降级页面或公共 API 字段。

章末题组原有的“初稿 → 主模型复算并返回最终题组”继续保留；移除的是后续内容修补之后的再次模型审核。
