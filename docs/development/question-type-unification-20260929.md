# 自定义题型协议与示例统一记录

日期：2026-09-29。范围：网页版单次文本题型。六个默认示例统一采用 V2 通用文本协议；V1 作为旧包和历史数据的兼容输入。没有引入另一套编译定义或执行引擎。

六个包都使用 `aiteachme.question-skill/v2`、`generic_text_form_v2`、`structured_subjective_v1`、`structured_text_v1` 和 `rubric_llm_v1`。包格式、题型内容版本与执行能力版本相互独立，执行能力无需随示例升级重命名。

- 示例源码目录和下载标识使用稳定题型身份。列表新增 `example_id`，前端按它区分六个共用模板的示例；旧 `_v1` / `_v2` 下载地址仍解析到相应当前示例，响应 `template_key` 标记弃用并保留下载兼容。
- 新题型继续复用 `CompiledQuestionTypeDefinition`、字段组件、生成与自动评分流程。四类 V1 模板的字段和协议识别集中到 `shared/kernel/question_type_compatibility.py`，原费曼出题行为集中到 `examine/question_types/legacy.py`。
- V2 新增可选 `generation_constraints.numbered_task_count`，允许声明 1–8 项编号任务。当前费曼包声明 4 项；通用生成器负责提示和校验，不按费曼包名分支。回归用另一个包名和两项任务验证相同能力。
- 新参考答案使用字段映射；写入题库时，兼容展示文本由同一份字段答案生成，避免单字段参考对象与展示文本不一致而导致课程导出后无法再导入。

## 迁移与兼容

四个原 V1 示例以相同 `package_key` 发布 2.0.0。字段 key、顺序、标签、长度限制、提示词、rubric、权重、通过阈值和案例预期评分区间均保持原值。原有两个 V2 示例仅调整源码目录名称，发布包字节不变。对照证据见 [迁移合同](../../backend/tmp/question-type-unification-20260929/migration-contract.json)。

V1 的多字段参考案例原为整段说明，新包使用现有强答案提供字段化参考答案，并将原说明保留在案例解析中。V1 先前未检查部分正确/错误案例的最低字数；迁移时将不足字数的案例补成完整表述，保留原有观点、误解和预设评分区间，使其符合题型自己的输入约束。

原四个 V1 源码和发布文件保存在 `backend/tests/fixtures/question_type_packages/v1/`。测试确认原包可按字节重新构建，原格式仍可导入。升级后沿用同一课程注册项，新旧版本分别保存；旧题快照、包哈希和评分合同不会被新版本覆盖。没有批量改写用户课程中的既有题型。

使用方式：进入训练中心的题型页，下载当前示例并导入。已有 V1 示例导入对应 2.0.0 包后新增版本并可设为当前版本；旧试卷继续使用冻结版本。创建独立题型时使用新的 `package_key`，更新已有题型时增加 `version`。具体编写合同见 [V2 规范](../standards/atqskill-v2.md)。
