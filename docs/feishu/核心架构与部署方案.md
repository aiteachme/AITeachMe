AiTeachMe 核心架构与部署方案

本文档记录了 AiTeachMe 项目当前 MVP 阶段的技术架构、仓库结构树以及前后端分离的自动部署 (CI/CD) 机制。

📍 项目地址 (Live Environments)

项目地址：https://github.com/aiteachme/AiTeachMe

- 前端访问地址 (Cloudflare Pages): https://aiteachme.pages.dev
- 后端 API 服务 (Render): https://aiteachme.onrender.com/api/health
⚠️ 注意事项: 后端 API 托管在 Render 的免费实例上。如果超过 15 分钟没有请求传入，服务会自动进入休眠状态。因此，您在长时间未访问后首次打开网站时，加载数据可能会有 30~50 秒的“冷启动”延迟，这属于正常现象。

🛠 技术栈概览
项目目前采用极简、现代、且易于免费托管的架构：
- Frontend (前端): Vite + Vanilla JS (原生 JavaScript/HTML/CSS)，不依赖笨重框架，做到极致轻量。
- Backend (后端): FastAPI (Python 3) + Uvicorn 异步 Web 服务器，提供自动生成的交互式 API 文档。
- Deployment (部署与托管):
  - 前端: Cloudflare Pages (全球边缘节点 CDN 加速，支持私有仓库极速构建)
  - 后端: Render Web Service (免绑卡，提供稳定的 Python 运行环境)
- CI/CD (持续集成/部署): GitHub Actions + Webhooks

---

🚀 自动化部署流程 (Deploy Hooks)
我们没有使用传统的“在 CI 中执行打包再上传”的复杂模式，而是直接利用部署平台提供的 Webhooks (Deploy Hooks) 来实现 “Push 即上线”。

1. 提交代码: 开发者在本地完成功能开发后，执行 git commit 并 git push 到 GitHub 的 main 分支。
2. 触发 Action: GitHub Actions 监听到 main 分支发生推送，自动启动流水线任务 (.github/workflows/deploy.yml)。
3. 调用 Hooks: 脚本向 Cloudflare 和 Render 的指定 Webhook URL 发送 POST 触发请求。
4. 各自构建发布:
  - Render (后端): 收到通知，拉取 backend/ 目录最新代码，执行 pip install 和重启服务动作。
  - Cloudflare (前端): 收到通知，拉取 frontend/ 目录最新代码，执行 npm run build，并将打包产生的 dist 分发至云侧 CDN。
这种设计的好处：
完全解耦。不需要在 GitHub 里保存部署平台的秘钥，也不占用 GitHub Action 的打包算力，把构建过程全权交给最专业的托管平台自己处理。
