这组文档只保留开发时最常用的入口。更细的事实源以代码附近的 README、内部 `docs/` 和 OpenAPI 为准。

## 先记住三件事

1. 前端在 `frontend/`，后端在 `backend/`，展示文档在 `docs/content/docs/`。
2. 后端业务逻辑优先放在 `backend/app/workflows/`，不要绕过它在 API 层拼复杂流程。
3. `frontend/src/api/generated/` 是 Orval 生成物，不手动修改。

## 推荐入口

| 区域 | 职责 |
| --- | --- |
| 本地启动 | [本地开发](/docs/developer/local-development) |
| 后端分层 | [架构总览](/docs/developer/architecture) |

| 前后端契约 | [API 契约](/docs/developer/api-contracts) |

## 修改前检查

- 改后端长链路时，确认前端是否需要进度事件或失败摘要。
- 改 API 时，确认 OpenAPI 和 Orval 生成物是否要同步。
- 改文档站内容时，优先保持默认 Markdown / Fumadocs 样式。
- 提交前至少跑受影响模块的构建或检查。
