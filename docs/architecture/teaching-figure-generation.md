# 教学图示生成方案

## 目标

DocGen 的静态图示只做“图”，不做正文摘要、流程卡片、对照表或目录清单。它应该能覆盖常见课程里的简单题图和示意图，例如几何题图、函数曲线、椭圆、受力图、电路图、地图区域、经济曲线或结构关系图，但不能把某个学科的图形模板写死在后端。

## 方案调研

### 1. 文生图

不适合作为默认路线。原因是教学图需要可读标签、稳定几何关系和可追溯事实，通用文生图很容易把坐标、公式、点名、角度和题设关系画错，且难以做自动校验。

### 2. TikZ / LaTeX

优点是排版和数学图质量高，适合高精度几何、函数、物理图。`standalone` 可以把单张 TeX 图独立编译；`dvisvgm` 可以把 TeX/DVI/PDF 结果转成 SVG。

不适合作为当前默认主链：运行环境必须安装 TeX 工具链，编译耗时和失败模式都更重，沙箱、安全、字体和中文处理也需要额外运维。它更适合作为后续“高质量离线增强器”：当部署环境检测到 `xelatex/pdflatex + dvisvgm` 可用时，把同一份结构化图元转成 TikZ 再编译。

### 3. 直接让 LLM 输出 SVG

适合简单线条图，但不能直接信任原始 SVG。模型可能输出脚本、外链、过长文本、无关装饰或不可维护的坐标结构。默认路线不让模型直接写 SVG，而是让模型输出受控 `FigureSpec`，由后端 renderer 统一生成 SVG。

### 4. HTML + 图形库

JSXGraph、D3、Observable Plot 这类库很适合交互几何、函数绘图和数据可视化。但它们引入前端脚本依赖，适合已有的 interactive HTML sidecar，不适合作为静态讲义图的默认链路。静态图示需要更轻、更可控、更容易校验。

## 当前落地路线

默认采用：

```text
章节片段
-> LLM 规划 FigureSpec
-> source_refs / schema / 几何图元校验
-> 后端 renderer 生成单文件 HTML + 内联 SVG
-> 前端 sandbox iframe 展示
```

`FigureSpec` 是跨学科的图元 DSL，不是学科模板库。模型可以组合：

- `axis`：坐标轴、方向轴
- `curve`：函数曲线、轨迹、趋势线
- `point`：点、焦点、交点、端点
- `line` / `vector`：线段、辅助线、力、方向、位移
- `shape`：`ellipse` / `circle` / `rectangle` / `triangle` / `polygon` / `angle` / `arc` / `region`
- `label` / `callout`：短标签

后端只负责安全渲染这些 primitives，不根据“椭圆”“三角形”“导数”等关键词自动编造具体图。模型如果给不出可画图元，静态图示链路直接跳过，不用假图兜底。

## 质量边界

- 只生成 `problem_diagram`，不生成流程卡片、概念总结图、表格图或纯文字图。
- `source_refs` 必须回指当前章节片段；不允许图中出现正文没有支撑的新事实。
- 图内文字必须短，只放点名、轴名、变量、公式短标签和关系标签。
- renderer 只输出静态 SVG；无脚本、无外链、无任意 HTML。
- 每章最多自动插入少量高置信图，宁可少生成，也不要用“看起来像图”的文字整理污染讲义。

## 后续增强

- TikZ 后端：同一份 `FigureSpec` 可转 TikZ，并在工具链可用时编译为 SVG/PNG。
- 学科插件：不要写死模板，可以增加“图元规划器”的 few-shot 示例或专用子模型，但输出仍必须落到同一套 primitives。
- 交互图：需要拖动、滑块或动态参数时走 interactive HTML sidecar，不复用静态图示链路。
