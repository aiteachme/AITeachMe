# 交互式题型注册 V1 方案

状态：已撤销，待重新设计。日期：2026-09-07。

撤销记录：当前方案不符合产品要求，相关功能实现、接口与数据结构已经移除。本文仅保留为历史方案参考，不代表现有产品能力。

本方案聚焦一个“创建我的题型”入口、一个文字交互执行器、两个模板（知识答辩、教会 AI），以及可追溯对话证据的训练报告。目标是让用户创建自己的考查方式，保存后绑定不同课程知识点重复使用。

## 1. 产品定位与范围

V1 定位为个人形成性训练。用户能够选定已生成课程中的知识点，用自然语言定制考查方式，完成一段有目标、有边界的多轮训练，并查看哪些能力得到了证据支持。

| V1 必须完成 | 后续扩展 |
| --- | --- |
| 两个系统模板；自然语言创建、编辑、试跑、保存个人题型 | 公开题型市场、分享与协作编辑 |
| 同一用户跨课程复用题型；每次单独选择知识点 | 自动推荐题型、跨课程综合考查 |
| 文字多轮交互、针对性追问、提示、主动结束、断线恢复 | 语音、虚拟人、代码运行、图形实验组件 |
| 课程证据绑定、过程记录、独立报告生成 | 正式考试排名、高风险成绩认定 |
| 历史会话与报告、不可变版本、调用成本记录 | 自动优化个人 skill、正式研究数据集发布 |

建议默认每次选择 1–3 个知识点、6 次学生作答，上限 10 次；每场最多 2 次提示。预计时长展示为 5–10 分钟，作为预期提示，学生思考时间不直接计入成绩。轮次和调用预算由服务端执行。

V1 报告作为独立训练结果保存，暂不写入正式 Profile mastery_score。可读取现有掌握度作为出题先验，但报告必须以本轮实际证据为依据。后续校准后增加会话级 Profile 适配器，避免把多次相关追问当作多道独立正确题累计加分。

个人题型属于当前应用用户身份。沿用现有云端、访客、本地身份模型；不另行实现跨设备账号同步。

## 2. 用户流程与页面

### 2.1 从训练中心进入

训练中心新增“AI 互动训练”入口，展示两个模板、最近使用的个人题型和未完成训练的继续入口。现有题型展示页增加“系统题型 / 我的题型”视图，系统静态题型和交互题型以能力标识区分。

用户可以直接使用系统模板，也可以从模板创建自己的版本。

### 2.2 创建个人题型

1. 选择“知识答辩”或“教会 AI”作为基础玩法。
2. 输入自然语言要求，例如“扮演面试官，先问原理，再用反例追问；回答太抽象时要求举例”。
3. AI 生成结构化训练卡，展示名称、目标能力、角色、追问风格、阶段、提示规则、评价维度和轮次上限。
4. 用户通过表单编辑或补充一句要求重新生成草稿；重新生成保留上一草稿，避免丢失手工修改。
5. 选择当前课程知识点试跑；试跑记录标记 preview，不进入正式训练历史汇总。
6. 保存可用版本到“我的题型”。修改已保存版本产生新版本，已有会话继续使用旧版本。

用户界面使用“题型 / 训练规则”等词，默认不展示内部 prompt、JSON 和运行时字段。对于当前无法支持的要求，如“画一张可拖拽电路图”，创建器解释支持边界并保留用户草稿，不伪装为已经实现。

### 2.3 开始训练

选择题型 → 选择课程知识点 → 查看本次范围、目标、轮次和提示规则 → 开始。

题型是可复用方法，课程范围是本次任务参数。个人题型版本不固化跨课程无效的知识点 ID；上次选择可以作为该课程的界面偏好保存。

### 2.4 训练界面

- 顶部：题型名称、知识点、当前阶段、作答次数；预计时长不做倒计时惩罚。
- 主区：AI 与学生的文字交互，支持课程已有 Markdown/公式渲染。
- 侧栏或移动端抽屉：公开训练目标、提示记录、当前流程；不显示内部答案、预埋误解的真值或未揭示的评分证据。
- 操作：提交、请求提示、结束并查看已有结果、退出稍后继续。
- 模型处理中禁止重复提交，刷新后恢复服务端状态；已接收的回答保留，即使后续模型生成失败。

每轮 AI 原则上只提出一个主要问题，保证学生知道当前要完成什么。改变角色口吻不得增加无关演绎和对话负担。

### 2.5 结果报告

报告包含总体反馈、逐知识点评价、原话证据、提示影响、尚未验证的能力和建议练习入口。点击证据跳转到对应轮次，点击课程依据打开相应文档位置。

历史列表能区分完成、提前结束、处理中和可恢复失败。再次练习复用同一题型版本或显式选择新版本，生成新的任务与情境。

## 3. 两个模板的行为规范

| 规则 | 知识答辩 | 教会 AI |
| --- | --- | --- |
| AI 角色 | 考官或讨论对手 | 有明确知识边界的模拟学生 |
| 开场 | 围绕目标知识点提出解释或判断问题 | 展示一段包含指定误解的理解，请用户讲解 |
| 主要过程 | 初答 → 依据缺失证据追问 → 反例或情境迁移 | 用户解释 → AI 基于模拟知识状态追问或尝试应用 → 用户纠正 |
| 自适应依据 | 当前仍未验证的目标、回答中的错误与过度概括 | 哪些误解已被用户有效纠正、哪些还缺解释 |
| 收尾 | 一个新的应用情境，尽量独立作答 | 要求用户判断一个新案例并说明理由 |
| 核心评价 | 正确性、因果解释、适用边界与迁移 | 正确性、解释质量、误解定位与迁移 |

知识答辩应允许学生修正观点。纠正错误是有效证据，不能以是否坚持立场或“赢过 AI”作为掌握判断。

“教会 AI”的模拟学生状态由任务预先定义，包括已知内容、未知内容和 1–2 个有课程依据的误解。每轮根据学生回答中的证据提出状态更新，服务端校验后应用。AI 自称“我懂了”不是用户掌握或教学成功的证据。

收尾新情境也计入作答预算，调度器提前保留一个作答名额。若用户提前结束或预算不足以形成完整证据，则输出部分报告并标记未验证项。

## 4. Skill 的定义与边界

Skill 是应用内部版本化的声明式训练定义，V1 不需要模型微调或任意生成代码。

```json
{
  "schema_version": 1,
  "display_name": "我的原理答辩",
  "runtime_kind": "dialogue",
  "template_key": "knowledge_defense",
  "role_description": "认真但友好的面试官",
  "target_capabilities": ["explain", "apply", "identify_boundary"],
  "follow_up_style": "回答抽象时要求举例，结论过强时给出反例",
  "stage_policy": ["opening", "probe", "transfer", "review"],
  "limits": {"max_answer_turns": 6, "max_hints": 2},
  "hint_policy": "on_request",
  "rubric_key": "knowledge_defense_v1"
}
```

V1 可自定义名称、角色、目标能力子集、追问偏好、提示策略、允许范围内的轮次。模板阶段、必需能力维度、结束规则和评价等级具有系统约束；创建器将用户要求编译到这些能力内。

复杂自由评分权重和任意阶段图延后。用户可以改变训练偏好，但每个任务开始时必须冻结评价目标和标准。跨个人题型的结果不直接排名。

编译流程：解析要求 → 生成结构化定义 → Pydantic 校验 → 能力/边界校验 → 最多一次修复 → 可编辑草稿。无需调用数据库或工具的自由 prompt 不视为可执行权限。

## 5. 本次任务的生成

每次启动会话时生成并冻结 task_snapshot，包含：

- skill_version_id、course_id、选定 KnowledgeUnit ID 与名称。
- 课程来源片段、文档/片段标识、版本或内容哈希、必要内容快照。
- 3–5 个可观察的考查目标及其知识点映射；目标数受作答预算限制。
- 评分要点、可接受解释、典型误解、适用边界。
- 首个问题或模拟学生的初始说法、初始模拟知识状态。
- 提示、结束和调用预算；模型、prompt 与检索策略版本。

生成顺序：知识点权限与状态校验 → 课程证据检索 → 目标与任务生成 → 来源和结构校验 → 冻结任务 → 首轮展示。

资料不足以支持所选目标时，提示缩小范围或补充资料；用户可修改后重试。不得仅凭模型常识伪造课程出处。

范围默认严格限制为用户所选知识点；课程中相关基础内容可用于解释上下文，但不得静默增加计分目标。知识点删除或资料更新后，旧会话仍引用启动时的证据快照，新会话重新校验。

## 6. 多轮执行与证据

会话循环：接收并保存动作 → 分析学生回答 → 校验并保存证据 → 服务端选择下一阶段/动作 → 生成 AI 发言 → 保存最终发言与状态。

两个逻辑职责分别调用模型：证据分析负责学生说了什么及其依据；对话生成负责下一轮怎样提问。最终报告通过独立评分调用生成。逻辑职责分开，不要求引入多个常驻 agent。

V1 调度以可解释规则为主：

1. 存在与当前目标直接相关的明显错误时，优先澄清该错误。
2. 回答缺少判断依据时，要求解释原因或举例。
3. 已回答的基础目标不重复问定义，转向未覆盖目标或适用边界。
4. 收尾名额到达时进入新情境迁移；目标已充分覆盖时也可以提前进入。
5. 达到轮次、提示或总调用预算后结束；不能让模型自行无限延长。

每条证据至少包含 objective_id、knowledge_unit_id、turn_id、学生原文引用、证据类别、简短判定依据、提示暴露信息及课程 source_ref。原文引用必须能在存储的学生回答中定位；模型生成的引用 ID 必须经过归属校验。

证据类别采用 supported / partial / contradicted / unobserved。提示后产生的证据额外标记 assisted，不覆盖之前的独立作答记录。后续答对不会删除先前的误解记录；报告展示修正过程。

针对同一目标、同一轮的证据使用稳定键去重。未验证等于缺少证据，不等于回答错误。模型自报置信度不作为已经校准的掌握概率。

## 7. 报告与评分

V1 主结果使用“已展示 / 部分展示 / 存在误解 / 证据不足”，逐项展示依据；暂不生成一个缺乏校准依据的总掌握百分比。

报告生成读取冻结任务、完整问答、提示暴露和证据记录，按固定版本标准独立判断。前序证据作为可核验输入，报告评分器可以指出证据与原文不匹配，但不能无依据补造证据。

报告必须回答：

1. 本次训练原本要验证哪些目标？
2. 哪些能力由独立回答支持，哪些依赖提示？
3. 哪句话体现了正确理解、误解或修正？
4. 哪些目标尚未被充分考查？
5. 下一次应该练什么，为什么？

输出附带覆盖度，例如“5 个目标中 3 个有充分证据”，同时明确目标完成数不等同于长期掌握率。提前结束也能生成报告，空会话只显示训练未完成。

## 8. 数据结构与现有系统衔接

复用 QuestionTypeRegistry 作为唯一题型目录；扩展它支持交互执行和用户归属。现有静态题型、出题链及试卷数据继续使用原有模型。

| 表 | 新增或调整职责 |
| --- | --- |
| QuestionTypeRegistry（扩展） | owner_user_id、runtime_kind=static/dialogue、current_version；支持 scope=user |
| AssessmentSkillVersion（新增） | 题型 ID、版本号、draft/compiling/ready/failed 状态、原始要求、结构化定义、冻结时间和错误信息 |
| AssessmentSession（新增） | 用户、课程、skill_version_id、task_snapshot、当前状态与阶段、模拟学生状态、轮次/提示计数、revision、报告请求、执行租约和预算 |
| AssessmentTurn（新增） | 会话序号、client_action_id、request_hash、动作、学生内容、AI 内容、证据 JSON、处理状态、执行租约、尝试次数、模型/prompt 版本、调用用量 |
| AssessmentReport（新增） | session_id 唯一、状态、报告 JSON、评分规则和模型版本、生成/失败元数据 |

概念上仍有 Skill、Task、Session 三层；V1 Task 使用会话内不可变快照，避免提前增加单独任务复用表。证据先作为结构化 JSON 存在每轮与报告中，未来分析需要时再独立建表。

注册表唯一约束调整为 scope + owner_user_id + course_id + type_key。owner_user_id、course_id 在不适用的作用域使用统一空值约定；服务端校验 global/course/user 的组合。个人 type_key 由服务端生成，名称允许重复。

同一个用户题型可跨其有权访问的课程使用；所有会话、版本、课程片段和报告均从服务端身份校验归属。归档题型禁止新建会话，既有会话仍可恢复与回看。

系统模板作为 runtime_kind=dialogue 的注册记录及不可变版本种入。旧 question-types 接口仍返回五类静态类型，新增目录接口供新页面聚合展示。静态生成器的 Literal 不直接放开成任意字符串，由入口根据 runtime_kind 分发。

交互题型 V1 通过独立训练入口启动；与纸质考卷混合组卷延后。交互历史独立展示，不伪造 ExamPaperItem 或标准答案来承载整段会话。

## 9. API 草案

接口名称在实现阶段按仓库路由约定细化，以下为职责合同。响应沿用 ApiResponse，OpenAPI 生成前端类型和客户端，不手改生成产物。

| 接口 | 职责 |
| --- | --- |
| GET /courses/{course_id}/exams/type-catalog | 聚合当前可用的静态、系统交互与个人交互题型 |
| POST /assessment-skills/drafts | 创建题型记录与编译中的草稿版本，后台编译，返回 ID 与状态 |
| GET /assessment-skills/{id}/versions/{version} | 查询草稿编译状态或读取可访问版本 |
| POST /assessment-skills/{id}/versions | 从已有版本创建新草稿 |
| PATCH /assessment-skills/{id}/versions/{version} | 编辑未冻结草稿；自然语言重新生成必须基于指定 revision |
| POST /assessment-skills/{id}/versions/{version}/activate | 校验并冻结版本，更新当前版本；直接表单修改也必须校验 |
| POST /assessment-skills/{id}/archive | 归档个人题型 |
| POST /courses/{course_id}/assessment-sessions | 指定版本、知识点和启动幂等键，创建并准备任务；支持 preview |
| GET /courses/{course_id}/assessment-sessions | 本课程训练历史，默认排除 preview |
| GET /assessment-sessions/{id} | 获取公开会话快照、轮次及已完成报告 |
| POST /assessment-sessions/{id}/turns | 提交 answer/hint 等动作，携带 client_action_id 与 expected_revision |
| POST /assessment-sessions/{id}/finish | 幂等请求结束，等待已接收动作处理完后生成报告 |
| POST /assessment-sessions/{id}/retry | 重试明确可恢复的准备、轮次或报告任务；沿用原输入身份 |
| GET /assessment-sessions/{id}/events | SSE：公开状态、发言草稿、最终发言、报告完成、错误 |

开始、提交与结束返回已接收状态，后台任务通过持久化租约执行；数据库连接不跨长模型调用持有。SSE 断开不取消已接收的工作，前端通过快照恢复。

SSE token 草稿允许断线后丢弃，最终消息与会话 revision 必须持久化；客户端重连以服务端快照为准并按 turn_id 去重。不得把内部证据分析、答案、模拟误解真值或推理过程发往训练中的客户端。

## 10. 状态、重试与调用预算

```text
preparing -> active -> reporting -> completed
                 \-> finish_requested -> reporting

可恢复失败保存 failed_stage 与原工作 ID；修复后回到相应步骤。
退出页面保留会话，重新进入从服务端快照恢复。
```

active 状态下每次最多处理一个学生动作。相同 client_action_id 和相同请求体返回原结果；同一键不同请求体报冲突；过期 expected_revision 阻止双标签页向旧问题作答。失败重试不再增加一次有效作答。

结束与在途动作通过 session revision/锁串行化。先接收的回答先处理，随后冻结记录用于评分；进入 reporting 后拒绝追加新答案。后台重启通过待处理记录和租约恢复，避免永久处于“AI 正在思考”。

建议初始模型配置：定义编译与证据提取使用 primary，任务构建、对话生成和报告使用 reason；实际槽位沿用已有模型策略配置。每次调用最多一次自动重试，服务端限制总调用与 token 预算。持续性模型失败显示可恢复错误，不返回虚构合格结果。

云端灰度前接入现有额度预留/结算能力，覆盖草稿编译、试跑和正式会话。按实际模型试运行数据设置可配置额度；本方案不预设人民币价格或照搬一次静态组卷成本。相同工作幂等键只结算一次。低预算时应预留报告生成额度，不能把预算全部消耗在追问上。

每个 workflow lane 按 graph.py、state.py、nodes/、lib/、prompts/、README.md 组织。skill_build 负责定义编译，interactive_assessment 负责任务准备、单轮执行和报告的明确入口；不把整个跨请求会话放在一个长生命周期图调用中。

复用现有身份、课程权限、LLM model policy、后台注册器、流式基础设施、Markdown 和知识点选择能力。检索通过适当的稳定导出或抽出实际共享函数复用，不直接依赖聊天私有节点，也不调用会直接讲解答案的完整教学聊天流程。

ExamsPage 只承接入口和目录整合，新会话与编辑器独立组件化。现有 exams.py 已承载大量逻辑，新 API 不继续堆入该文件。

## 12. 开发顺序与交付门槛

以下为一名熟悉仓库的全栈开发者的初步人日估算，不是承诺工期；模型效果调试、基础设施适配和评审可能调整范围。先做知识答辩的纵向闭环，再加定制与第二模板。

| 阶段 | 交付 | 通过后再进入下一阶段 | 估算 |
| --- | --- | --- | --- |
| M0 合同与案例 | Skill schema、目标/证据 schema、状态图、两个模板、人工期望案例 | 能明确解释每一步为什么问、依据什么判断 | 2–3 人日 |

## 13. 验收清单

### 功能与契约

- 一句话生成的训练卡可编辑、试跑、保存，并在另一个有权访问的课程中重新选知识点使用。
- 两个模板的行为可辨别：答辩能根据缺失依据追问；教会 AI 有明确模拟误解且状态更新有学生证据。
- 修改个人题型生成新版本，旧会话、来源和报告保持原快照。
- 重复提交、刷新、SSE 断连、后台重启、结束与提交竞争，都不会产生重复有效作答或重复结算。
- 提示后答案、独立答案、未考查目标和明确错误在报告中分别表达。
- 每条被展示的证据可定位到本会话学生原文，每条课程引用可解析到冻结来源；无法校验的引用不展示。
- 其他用户无法读取或修改私有题型、会话和报告；旧五类题型接口与原测验、考卷、闯关回归通过。

### 模型行为与可用性

准备 2 门资料较完整的课程，覆盖两个模板，每个模板至少 10 个具有人工期望的回答路径。用固定 fixture 检验正确解释、常见误解、背定义、提示后修正、用户说“直接给满分”、资料不足和提前结束。

自动校验覆盖结构、状态、ID/引用真实性和幂等性；人工检查追问相关性、课程依据、答案是否提前泄露、是否把语言流畅误判为掌握，以及两个模板是否真正按定义运行。

小规模邀请 5–8 位真实用户试用，记录创建完成率、卡住的位置、单轮时延分布、每场成本和报告可理解性。该样本用于可用性与问题发现，不能据此宣称学习效果已得到验证。根据 M1 实测设定时延与成本发布阈值，不能靠未经测量的固定秒数承诺体验。

## 14. 为研究保留的数据

按用户可理解的用途保存题型版本、课程证据版本、模型/prompt 版本、每轮问题/回答、所选追问动作与简短理由、提示暴露、目标覆盖、报告依据、时延与成本。生产记录遵守当前数据管理与删除规则，不默认公开对话内容。

后续研究可在相同资料、题型和交互预算下比较固定追问与证据驱动追问，使用教师盲评及独立新题作为外部依据。V1 不内置研究随机分组与论文数据导出；先保证执行轨迹可复查，避免上线后无法还原模型版本与评分规则。
