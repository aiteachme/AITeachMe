## 2. 产品概念与首发题型

题型包包含元信息、出题提示词、作答结构、评分规则、参考案例、图片资源以及系统工具绑定。用户可修改示例包，导入自己的课程题型；运行模板与组件固定为系统已实现的能力。

| 模板 | 题目内容 | 学生提交 | 核心评价 |
| --- | --- | --- | --- |
| feynman_explanation_v1 费曼解释 | 概念、目标听众、解释要求 | 一段通俗解释 | 准确性、解释依据、有效例子、适用边界 |
| oral_defense_v1 书面答辩 | 命题、结论或方案及论证要求 | 结论、依据、边界 | 结论与证据匹配、论证完整、限制明确 |
| scenario_interview_v1 情境面试 | 场景、约束与任务 | 分析、步骤、结论 | 原理应用、方案有效、取舍合理 |
| argument_debate_v1 结构化辩论 | 议题、背景和反方观点 | 立场、论据、反方观点、反驳 | 事实正确、论证有效、回应反方 |

表中的中文是产品含义；作答字段的实际 key、顺序以各现有示例和权威 Schema 为准。用户可修改显示名称、标签、占位文案、长度、prompt、评分维度与权重，在现有模板合同内形成个人化题型。

一个包定义一种题型；一种题型可以生成多道题；一道题可以被不同试卷或闯关使用。题型定义、题库内容和用户答案必须分别保存。

V1 安装范围为当前课程、当前应用用户。跨课程复用可再次导入同一包；账户级题型库、分享市场和多人协作另行扩展。

## 3. 页面与导入流程

沿用用户截图中的课程题型页布局，在标题右侧增加“导入题型”和“下载示例包”。保留概览、搜索、筛选和题型卡片。

1. 用户选择 `.atqskill` 或内容符合相同合同的 `.zip`。ZIP 后缀别名在上传适配层处理，不改变包内校验。
2. 上传到临时记录，执行已有格式校验与编译，并检查所需执行器、评分器和工具是否可用。
3. 展示名称、版本、说明、来源、作答示例、评分维度、模式能力及版本冲突情况。
4. 用户点击“导入到本课程”，服务端使用暂存的编译结果创建注册项及不可变版本。
5. 安装成功后刷新课程题型目录和概览计数。运行时、结构化文本组件、评分器和必需工具均已发布的题型可进入对应模式配置；能力缺失的题型保留在目录中并显示原因。

新卡片显示“用户上传 / 课程题型”、版本、AI 评分和支持模式。题型详情支持查看公开规则、导入新版本、启用/停用。首版采用停用或归档，不物理删除被题目引用的版本。

搜索筛选增加来源与状态维度，保留现有题型分类。筛选隐藏刚导入的题型时，应提示并可一键定位。导入错误要定位到文件或字段；格式校验不调用 LLM。

“运行参考案例”可作为导入后的可选自动质量检查，展示模型评分、时延和调用用量。格式通过只说明合同合法，不能显示为模型出题和评分效果已经验证；无需人工审批或提供供应商价格才能安装、生成和评分。

## 4. 文件包结构与职责

```text
my-question.atqskill              # ZIP 容器
├── SKILL.md                      # YAML Frontmatter + 人类可读说明
├── prompts/
│   ├── generate.md               # 生成题目、参考答案、评分依据
│   ├── grade.md                  # 对实际题目和学生回答评分
│   └── feedback.md               # 可选：反馈与解析的表达规则
├── references/
│   └── cases.json                # 题目 + 优质/部分/错误回答案例
├── tools/
│   └── bindings.json             # 系统工具 ID 及 required 标志
└── assets/
    └── illustration.png          # 可选：清单声明的图片
```

沿用当前 `references` 拼写。未在清单引用的文件仍按现有规范处理，不自动扫描任意 Markdown 拼接 prompt。

| Frontmatter 字段 | 含义 |
| --- | --- |
| schema、package_key、version | 协议、包身份和包版本 |
| name、description | 题型名与简单描述 |
| template_key | V1 四个固定模板之一；V2 使用 generic_text_form_v2 |
| runtime_key、renderer_key、grader_key | 系统执行器、组件与评分器 |
| capabilities | 训练模式、提示和即时反馈能力 |
| files | 实际生效的 prompt 与案例路径 |
| answer_schema | 字段、控件、必填与长度 |
| grading | 维度、权重和通关阈值 |
| tools、assets | 工具绑定和资源清单 |

来源 `source` / `is_system`、用户、课程、状态和存储路径由安装端填写，包不能自称系统内置。`SKILL.md` 正文仅供说明；作者的 guideline 可合并到正文或显式出题 prompt 中，不新增当前 Schema 不接受的文件引用。

参考案例包含 question.stem、reference_answer、explanation，以及 strong / partial / wrong 三类回答、预期分数区间与是否通过。主观题使用参考答案和评价标准，不做唯一字符串等值判定。包内示例提供风格和评分例子；实际题目必须根据当前课程知识点生成。

保留当前包边界：图片为 PNG/JPEG/WebP；`tools/check_answer.py`、`assets/xxx.py` 和 HTML 等不在 V1 接受范围内。对应 check_answer 的真实实现放在服务端，包通过 bindings.json 引用系统工具。未来可执行文件与静态实验环境需独立沙箱运行时、权限和预算设计，不混入本版导入器。

导入继续使用现有校验限制：压缩包 8 MB、解压总量 24 MB、最多 100 文件，校验不执行磁盘解压或包代码。P1 另限制每课程 10 个待确认导入、20 个上传题型、每题型 10 个版本、100 MB 已安装图片资源，以及每账号 20 个待确认导入。资源存储只接受编译器校验通过的内容，以 hash/内部资源 ID 引用，不能把整个包直接挂到前端静态目录。

## 5. 工具与真实能力检查

协议白名单包含 rubric_coverage_v1、keyword_match_v1、math_equivalence_v1 和 json_schema_validate_v1，当前执行器只提供 rubric_coverage_v1。导入安装检查真实执行能力，不能把协议白名单当作实现完成。

P2 已实现费曼模板所需的 rubric_coverage_v1 和结构化字段校验。安装器按实际能力决定是否激活运行；必需工具或执行器缺失时继续禁止激活。

工具接收服务端整理的题目、rubric 与作答，返回结构化观察，不直接写成绩、不读取任意课程。需要 LLM 的工具同样走既有模型 helper 和调度器，不创建独立 provider 客户端。

包的 capabilities 表示允许能力，实际能力是包、执行环境、模式规则三者的交集。提示功能没有实现时不能只因包声明 hints=true 就显示可点击按钮；模式禁止提前反馈时不执行或不展示该能力。

## 6. 课程注册、版本与存储

`QuestionTypeRegistry` 保存课程入口、来源和状态；`QuestionTypePackageVersion` 保存不可变的 compiled definition、版本、package hash、所有者和 `is_current`，运行合同只以冻结版本为权威来源；`QuestionTypePackageAsset` 保存校验后的资源；`QuestionTypePackageImport` 保存 24 小时上传暂存。确认安装只从服务端暂存记录取回编译结果。

冲突与更新规则：

- 同课程同 package_key、同版本同规范化 hash：幂等返回已安装结果。
- 同版本不同 hash：报冲突，要求增加版本或改 package_key。
- 新版本：新增版本记录，导入预览明确是否将其设为当前版本，不覆盖旧版本内容。
- 停用后不参与新组卷、补题和抽题；已开始试卷仍可根据快照作答、评分、回看。
- 删除课程与资源清理遵循已有生命周期；被历史题引用的版本与资源不得提前清理。

现有编译器生成 `custom_<package_key>`。类型解析必须带课程与所有者上下文；内置类型不能被上传包覆盖。包身份采用 key/version/hash，数据库引用使用 registry_id/version_id，名称允许重名。

浏览器获取公开名称、作答 schema、模式能力和允许的资源 URL；完整 compiled_definition、评分 prompt 与私有参考答案留在服务端。序列化 DTO 明确区分公开信息和评分私有数据。

## 7. 三种训练模式与题库

| 场景 | V1 行为 |
| --- | --- |
| 测验 | 按所选类型生成题目，渲染单次作答组件，整卷提交后评分与解析 |
| 考卷 | 按题型分组，提供对应作答栏，支持在线填写与学生版 PDF，交卷后评分 |
| 闯关 | 从符合配置的题库抽题，缺数量或题型时按包规则补题；逐题判分，通过阈值后出队 |
| 题库 | 保存生成的具体题目、参考答案、解析、知识点和题型版本，支持详情、筛选、标记和单题练习 |

闯关保持现有一次性作答语义；新增题型分数和通关结果用于本轮，不新建长期交互会话。

即使包声明 immediate_feedback=true，测验和考卷也服从交卷前不公布答案的规则。PDF 学生版只包含题干、材料和作答栏；答案解析输出复用现有解锁策略。

导入不会自动给课程批量出题。用户在测验/考卷配置中选用才生成；闯关选用后按需补题。导入只改变可选目录，空类型选择仍沿用原内置自动搭配，避免默认训练被导入行为悄悄改变。

## 8. 出题链改造

```text
读取课程已启用题型与版本
  → 冻结本次配置中的类型版本
  → 筛选课程知识点
  → 分配每题的类型、难度和知识点
  → 内置题走原生成器；上传题走包生成适配器
  → 校验题目、参考答案、rubric、知识点和资源引用
  → 写 QuestionTemplate 与知识点链接
  → 测验/考卷写 ExamPaperItem 快照
```

继续使用现有 question_build 主链，增加目录解析与生成 dispatch。配置接口、逐题要求、蓝图、生成 schema、评分路由、前端选项和闯关补题必须成套支持动态类型，不能只删除五类 Literal 校验。

新请求统一使用 `question_type_selections`：每项选择内置 `question_type` 或上传类型 `registry_id`，上传类型可选固定 `version_id`，各项可指定 `count`。数量须全部指定且总和等于题量，或全部省略由服务端均分；前端目前采用均分。统一字段不能与非空的旧选择字段同时提交。旧客户端的 `question_types` 与 `question_type_registry_ids` 仍兼容，并支持混选。服务器冻结实际采用的版本与配额；选定类型数量大于题量时，在配置阶段提示调整，避免静默漏掉类型。

上传类型使用当前确定性题型轮换/考卷分组逻辑的通用版本；分组不能只遍历内置五类。指定知识点范围新增 ID 参数并严格校验归属、过滤候选，不仅拼入 user_prompt。

新类型输出统一题目 envelope：stem、public_payload、reference_answer、reference_explanation、grading_spec、knowledge_unit_refs。具体 answer_schema、评分维度和模板约束来自冻结版本，模型不能临时发明新组件或修改题型合同。

prompt 由系统输出合同、显式包 prompt、服务端课程/任务上下文组装。现有变量遵守白名单；评分所需实际题干、参考答案、学生回答由服务端上下文注入，不擅自增加当前 Schema 不支持的 `${student_answer}` 等变量。

配置 hash、预生成匹配和复用条件纳入题型版本/hash与指定知识点范围，防止升级后错误复用旧定义的未开始试卷。生成中快照固定，用户随后升级包不影响本轮。

## 9. 题库、作答与组件

QuestionTemplate 增加 type_version_id、结构化 public_payload、reference_answer 与 grading_spec；内置题兼容现有字段。ExamPaperItem 冻结相同题目内容、作答 schema、评分规则、版本和题目满分。

现有 course_id + stem_hash 去重会合并不同题型的同题干，需同步调整唯一约束和 upsert。建议保留 stem_hash 用于文本检查，新增 identity_hash 表示题目身份：自定义题包含题型版本与规范化题干，内置旧记录按兼容规则回填。不能只新增版本列而让旧去重逻辑继续覆盖答案。

前端每一道题由统一 QuestionHost 承载：

```text
QuestionHost
  ├── 原五类题型 renderer
  ├── long_text_v1           # 费曼解释
  └── structured_text_v1     # 答辩、面试、辩论及 V2 自由文本字段
```

组件输入为 question、answer_schema、capabilities、mode、value、readonly 和事件回调。包选择系统组件与功能插槽，不上传 React 代码。打印采用独立布局适配，结构化字段按标签生成作答栏。

新增结构化答案 JSON，例如书面答辩的 {"claim":"…","evidence":"…","boundary":"…"}；实际 key 服从对应包 schema。服务端校验字段和长度并保存 schema 版本，旧 answer_content 保留稳定兼容展示。请求幂等指纹基于规范化内容生成；相同键不同答案仍返回冲突。

渲染适配必须覆盖测验工作区、考卷画布、闯关、题库详情、解析、历史和 PDF；题型停用后的历史内容仍按快照展示。未知执行器的旧题至少能够只读查看冻结内容，并明确不能重新启动执行。

## 10. 评分与结果

```text
解析冻结版本
  → 验证作答结构
  → 执行允许的系统工具
  → 应用 grade prompt 与参考答案
  → 校验各维度分数和学生证据
  → 服务端求总分、判断是否通过
  → 生成反馈和解析
  → 回写题目与试卷结果
```

每个维度返回 0–1 分数、学生原文证据、遗漏或错误和简短说明。原文引用必须在存储的学生回答中可定位；模型无法生成有效结构或引用时修复/重试，最终失败标为评分失败，不能以默认零分代替。

```text
score_ratio = sum(weight_i × criterion_score_i)
score_obtained = item.score_max × score_ratio
passed = score_ratio >= pass_score
```

服务端验证权重归一、维度齐全、数值边界和阈值，并使用冻结的满分。包、学生输入和本轮模型均不能覆盖系统状态或临时改评分权重。空白作答按未作答处理，格式非法与模型失败分别返回明确状态。

结果复用 score_obtained、is_correct、feedback_text，增加 grading_detail_json 保存维度与证据。解释使用“参考答案/评分要点”，允许不同正确表达。反馈优先复用同次结构化评分结果，可选 feedback prompt 仅调整表达，不重新决定分数。

上传题型计入本次试卷得分，标识为个人规则评分。V1/V2 对这些类型固定 `profile_eligible=false`，Profile 更新会过滤它们，原内置题继续原链；全自定义试卷不以个人 rubric 改写长期 mastery。后续若接入画像，必须先单独完成评分校准与发布验证。

## 11. 调度、可靠性与资源

遵守 workflows/README.md 中现有合同：批量出题、整卷评分、参考案例评估用 `run_llm_tasks(items, worker)`；单次 `acompletion*` 可以直接走既有 helper，底层已有共享 limiter。单题需要先后执行的步骤保持顺序，不为业务再创建并发池或用 asyncio.gather 直接批量发模型请求。

`llm.concurrency_limit` 当前是后端进程内共享并发预算，多进程全局配额不能据此假设已经实现。模型、最大 token、超时和重试由系统策略决定，包不携带 API key、provider 地址或并发设置。

LLM trace 记录 registry/version/package_hash、course/paper/item ID、阶段、token、耗时和错误。复用现有后台任务、SSE、额度预留/结算与失败恢复；临时上传不消耗模型额度，实际生成、评分和案例检查按各自任务计费策略接入。

确认安装、生成与提交保持幂等；评分失败保留原答案并支持重试，不能重复扣费或重复产生有效题目。私有包、prompt、案例答案与生成答案不放进公开静态目录；图片通过校验归属的资源接口访问。

## 12. API 与代码落点

P1 接口归于 `/api/v1/courses/{course_id}/question-types`，与执行期 `/exams` 路由分离：

| 接口 | 职责 |
| --- | --- |
| POST /imports | multipart 上传、校验、暂存及公开预览 |
| POST /imports/{id}/confirm | 幂等安装暂存包 |
| GET / | 内置和上传题型目录、真实运行状态 |
| GET /{id} | 公开详情、版本与状态 |
| PATCH /{id} | 归档/恢复、切换已安装版本 |
| GET /examples、/examples/{template_key} | 列出并下载四个 V1 与两个 V2 示例包 |
| GET /assets/{asset_id} | 校验课程权限后返回图片 |

原 generate、mastery-drill/prepare、question-templates、单题 grade 和 submit 扩展动态类型与结构化答案合同。API 返回公共 preview，不返回完整 compiled_definition。

安装用例进入已有 support/question_type_packages，新增独立 API 文件避免继续扩张 exams.py。模型与仓储保存版本、导入暂存和结构化题目。生成和评分分别在现有 question_build / exam_grade 接入派发；真正跨链共享的定义解析使用明确的共享包。

前端实现导入对话框、动态目录配置和 QuestionHost；通过 OpenAPI 重新生成客户端，不手改生成代码。新增运行合同和最终接口同步到对应模块 README；包文件协议保持以现有 Schema 和规范为准。

## 13. 实施顺序与验收

| 阶段 | 交付 | 完成条件 |
| --- | --- | --- |
| P0 复核基础（完成） | 构建/校验现有包、盘点工具与执行器差距 | 四示例合同通过，明确哪些能力还需实现 |
| P1 导入与目录（完成） | 上传预览、注册落库、版本、课程卡片、示例下载 | 导入后目录和统计更新，重复/冲突/归属正确处理 |
| P2 费曼纵向闭环（完成） | 一种包的生成、组件、评分、入库及三模式/PDF | 选导入类型后确实能完整生成并作答 |
| P3-A 协议与兼容（实现完成） | V2 字段协议与统一选择合同，保留 V1 | 同一内部定义承载新旧包，历史快照不重写 |
| P3-B 通用纵向链路（实现完成） | 结构化参考答案、字段验证、证据评分与薄 LLM 适配 | 字段 key 完整往返；无效证据不计分 |
| P3-C 展示与历史（实现完成） | 共用表单、草稿、只读、打印与导出导入 | 结构化答案在各入口保留；空白卷隐藏答案 |
| P3-D 混合与示例（实现完成） | 多种自定义题与内置题混选、配额、按类型补题 | 四字段与两字段示例共用同一执行链路 |
| P4 网页版验收（完成） | 18 条真实模型路径、96 项评分样例、浏览器与 PDF 已验；441 项后端、108 项前端回归通过；历史评分与现有额度逻辑已补验 | 在用户确认的网页版、LLM 自动生成/评分范围内闭环通过，模型质量观察详见 P4 审查 |

至少覆盖四示例 × 三训练模式共 12 个完整生成/作答/判分路径，另验题库单题、PDF 和含内置/上传题的混合卷。检查题量、类型分配、分值求和、学生版答案隐藏和报告显示。

关键回归包括：升级后历史题按旧规则评分；同题干不同类型不合并；停用不破坏旧试卷；配置 hash 区分版本；必需工具缺失不激活；模型失败不判零；重复请求不重复计分；PDF 不泄露答案或私有 prompt。

评分质量使用包内 strong/partial/wrong 回答及独立课程案例进行自动模型评估，记录评分区间偏差、判定一致性、时延和 token 用量。按与常规题相同的自动运行方式验收，不设置人工评分确认、API 实际费率或桌面/云端发布前置条件。

完成标准是“导入后可生成、可作答、可判分、可落库，并在三种模式中复用”。仅新增题型卡片不算完成。

## 14. 下一版扩展边界

多轮费曼、真正的 AI 辩论/面试/答辩需要新协议版本，增加交互 prompt 引用、轮次与结束规则、QuestionAttempt/Turn、服务端状态机和对话评分证据。按用户本次选择，不进入 V1 发布范围。

当前保留 runtime_key、renderer_key、grader_key、capabilities、版本快照与结构化题目等扩展点即可。不提前创建会话表、空执行器或新的多轮 schema。
