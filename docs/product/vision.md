# AITeachMe 产品愿景

AITeachMe 的愿景是：让天下没有难学的知识。

一句话定位：

> 把难以消化的学习资料，转化为可讲、可问、可测、可追踪的个人学习空间。

AITeachMe 不是一次性的文件摘要器，也不是普通聊天机器人。它的核心目标是让一门课程拥有可持续复用的学习上下文：资料被解析，方案被确认，文档被生成，图谱被沉淀，对话能追溯来源，练习能暴露薄弱点，画像能反哺下一次学习。

## 为什么要做

现代学习的瓶颈通常不是缺少资料，而是资料无法稳定转化为高质量学习行为：

- **资料过载**：PDF、讲义、笔记、论文、题库分散存在，学习者很难快速抓住主线和依赖关系。
- **理解不可验证**：看懂和会做之间有距离，缺少能把错因、薄弱点和复习任务串起来的闭环。
- **答疑不可持续**：通用 AI 可以回答问题，但很难稳定使用某门课程的资料、历史对话和掌握状态。
- **知识资产不可复用**：一次摘要、一次问答或一次练习很快过期，难以成为后续教学和复习的基础。
- **隐私与部署压力**：高质量学习资料常常敏感，本地优先和可自托管是教育场景的基本要求。

## 产品闭环

用户只需要把资料交给系统，AITeachMe 会围绕同一个课程空间完成学习闭环：

```text
资料进入系统
  -> Ingest 解析为标准 Markdown 与资产
  -> Digest 组织学习方案、知识文档和知识图谱
  -> Interact 基于课程知识进行伴读问答
  -> Examine 生成诊断练习并解释错因
  -> Profile 沉淀掌握度、薄弱点、复习任务和学习画像
  -> 反哺下一次对话、练习和学习计划
```

这个闭环的重点不是让模型“更会聊天”，而是让学习过程变成可积累、可观察、可改进的系统。

## 五大引擎

### Ingest：透视引擎

把当前开放上传的 PDF、DOCX、Markdown、TXT、JPG/PNG/BMP 等资料转成标准 Markdown 和资产目录。目标是先快、可预览、可恢复，再逐步增强复杂资料质量；复杂 PDF/OCR 场景可接 PaddleOCR 或 MinerU 外部链路。

### Digest：织网引擎

把资料组织成用户确认过的学习方案，再生成可阅读、可追踪、可复用的知识文档，并同步成知识图谱。Digest 是从“资料堆”走向“课程学习上下文”的主链路。

### Interact：伴读引擎

围绕课程、资料、知识文档、选中文本、错题和学习画像进行教学对话。目标不是直接甩答案，而是解释过程、追问盲区、引用上下文并引导理解。

### Examine：诊断引擎

基于知识单元、薄弱点和复习任务生成试卷，支持作答、判卷、错因解释和学习建议。它负责把“感觉懂了”转化为可验证的掌握证据。

### Profile：显影引擎

把每次学习、作答和复习沉淀为掌握度、薄弱点、复习任务、课程画像和 study plan。Profile 的目标是逐步积累学习上下文，而不是每次对话都从零开始。

## 当前产品边界

当前阶段优先保证：

- 本地优先可运行，普通开发和体验不依赖完整云端设施。
- 一个课程空间内资料、知识文档、知识图谱、对话、考试和画像互相打通。
- 后端 workflow、数据结构和文档事实源保持清晰，便于继续扩大系统能力。
- 可选外部服务缺失时尽量优雅降级，不阻断基础本地使用。

当前不追求：

- 一开始就覆盖所有通用 Agent 场景。
- 自动推翻用户确认过的学习方案。
- 把所有历史设计中的课程树、教学单元和复杂版本表一次性恢复。
- 为了展示效果伪造系统尚未承载的能力。

## 后续方向

AITeachMe 后续会继续围绕学习资料、课程知识和个人成长轨迹增强能力：

- **对个人**：把资料库变成可持续学习的个人课程空间。
- **对教师**：把课程资料转化为可发布、可诊断、可迭代的知识资产。
- **对团队**：把内部培训、考试、知识库和学习画像放到可自托管系统中。
- **对社区**：通过 `.atmx` 课程包、知识图谱和插件化工具，支持学习内容迁移和复用。

## 工程原则

- Course 是业务隔离边界。
- Workflows 是唯一业务层。
- Infra 只接能力，不决定教学策略。
- 证据优先，尽量让回答、文档和练习回到资料、引用、检索和图谱。
- 文档以当前事实为准，不保留会误导开发的旧权威稿。
