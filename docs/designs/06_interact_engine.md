# 06. Interact 引擎

## 1. 目标与职责
Interact 引擎负责把知识结构和学习者状态转成教学型对话。

它的目标不是做一个泛聊天窗口，而是做一个围绕当前学科资料展开的“学习陪练层”，重点包括：

- 基于资料和知识结构回答问题
- 基于薄弱点和错题调整回答策略
- 支持选段、证据、上下文驱动的问答
- 以流式方式提供教学反馈

对于 AITeachMe 来说，Interact 的核心价值不在“能聊”，而在“能教”。

---

## 2. 当前实现落点

当前代码里，Interact 主要落在以下位置：

- 前端页面：`frontend/src/pages/ChatPage.tsx`
- 后端资源组：`chats`
- 业务编排：`backend/app/services/chats_service.py`
- Agent：`retriever.py`、`context_builder.py`、`streamer.py`
- 核心对象：`ChatMessage` 与 SSE 事件结构

这说明当前项目已经具备最小可用的教学对话链路。

## 3. Pipeline 设计

### 3.1 教学对话主 Pipeline

| 步骤 | 子模块 | 输入 | 输出 |
| --- | --- | --- | --- |
| 1. 请求接入 | `ChatPage` + `/chats/send` | `question`、可选 `selected_context`、`source_chunk_id` | 对话请求 |
| 2. 查询向量化 | `retriever.build_query_embedding` | 用户问题 | 查询向量 |
| 3. 材料检索 | `retriever.retrieve` + `vector_search` | 查询向量、subject、top-k | 检索结果 `RetrievalResult[]` |
| 4. 学习状态加载 | `get_recent_turns`、`get_weak_points`、`list_mistakes_by_subject` | subject、用户上下文 | 聊天历史、薄弱点、近期错题 |
| 5. Prompt 装配 | `context_builder.build_chat_messages` | 问题、检索结果、学习状态、选段上下文 | 最终 messages |
| 6. 流式生成 | `stream_llm_events` + `acompletion_stream` | messages、请求上下文 | SSE `token` 流 |
| 7. 结果持久化 | `create_message_pair` | 用户问题、完整回答、contexts | `ChatMessage` 记录 |
| 8. 结束事件 | `format_sse_event(\"done\")` | `turn_id`、序列化 contexts | 前端可消费的完成事件 |

### 3.2 关键子模块输入输出

- 检索模块
  输入：问题文本、subject、检索参数。
  输出：相关 chunk、分数、标题路径、文档信息。
- 学习状态模块
  输入：subject、最近记录窗口大小。
  输出：聊天历史、薄弱点摘要、近期错题摘要。
- 上下文装配模块
  输入：检索结果、用户问题、选段上下文、学习状态。
  输出：最终提示词消息数组。
- 流式生成模块
  输入：消息数组、HTTP 请求上下文。
  输出：token 事件、error 事件、done 事件。
- 持久化模块
  输入：用户问题、完整回答、contexts。
  输出：`ChatMessage` 成对记录与可追踪 `turn_id`。

## 4. 核心设计原则

### 4.1 教学优先

Interact 的设计应优先服务以下场景：

- 概念讲解
- 解题引导
- 错题复盘
- 证据定位
- 学习建议

而不是追求开放域闲聊或泛助手能力。

### 4.2 对话必须绑定当前学科资料

Interact 不能脱离当前学科材料单独存在。设计上应继续坚持：

- 从学科知识材料中检索上下文
- 把检索上下文注入提示词
- 尽量让回答可以回到证据来源

### 4.3 学习者状态应进入上下文

教学对话不应只看当前问题，还应结合：

- 最近聊天历史
- 当前薄弱点
- 近期错题
- 用户主动选中的上下文

这会让系统从“会回答问题”升级成“会按学习状态辅导”。

### 4.4 对话模式要能分层

长期来看，Interact 最适合逐步发展为多种教学模式，而不是一个单一 prompt 吃掉所有任务。例如：

- 讲解模式
- 苏格拉底追问模式
- 错题复盘模式
- 选段精读模式
- 学习计划模式
- 文档伴读模式

设计时应尽量让不同模式可以挂在同一条主链路上。

### 4.6 文档伴读模式（KnowledgeDocsPage 右侧对话栏）

这是 Interact 引擎的一个重要消费场景。用户在 `KnowledgeDocsPage` 阅读知识文档时，右侧有一个 AI 对话栏，支持：

- 划线提问：用户选中文档中的一段文字，点击「提问」，选中文本自动作为对话的引用上下文
- 快捷提问：「解释这段」「举个例子」「这个会考吗」「和 XX 有什么关系」
- 上下文自动绑定：对话上下文自动绑定当前阅读的文档和章节
- 对话历史按文档分组：切换文档时切换对话上下文
- AI 回复中引用文档内容时，点击可跳转到文档对应位置

文档伴读模式与独立 ChatPage 的区别在于上下文装配策略：

| 维度 | ChatPage | 文档伴读模式 |
| --- | --- | --- |
| 主上下文 | 向量检索的 chunk | 当前文档的完整内容 |
| 焦点上下文 | 无 | 用户选中的文本片段 |
| 背景上下文 | 薄弱点 + 错题 | 薄弱点 + 该章节关联的知识图谱节点 |
| 对话历史 | 全局历史 | 按文档分组的历史 |

后端实现上，文档伴读模式复用 Interact 引擎的主 Pipeline，只是在请求中额外传入 `doc_id` 和 `selected_text`，由 `context_builder` 根据这些参数调整上下文装配策略。

### 4.5 来源可解释性很重要

教学场景下，用户经常需要知道“这段回答是根据哪里来的”。因此 Interact 的设计应优先保留：

- 检索命中上下文
- 最终引用来源
- 与图谱、证据弹窗、选段上下文的互通能力

## 5. 设计方法

### 5.1 查询理解

对话的第一步不是直接生成答案，而是理解用户当前是在做什么。常见教学意图包括：

- 问概念
- 问推导
- 问题解
- 问错因
- 问资料片段
- 问学习顺序

即便当前实现还没有显式意图分类，设计上也应把这层看作后续能力扩展的自然入口。

### 5.2 上下文召回

当前项目已经具备基于 `sqlite-vec` 的向量检索能力。对教学场景来说，召回层应重点考虑：

- 与问题语义相关的 chunk
- 与当前学科一致的材料
- 与用户当前选段一致的局部上下文
- 与薄弱点、错题关联的知识区域

这意味着 Interact 的检索不是普通搜索，而是“带教学状态的检索”。

### 5.3 上下文装配

上下文装配是当前 Interact 设计中的关键层。后续开发时，建议继续把上下文拆成几类再拼装：

- 检索上下文
- 最近对话历史
- 薄弱点摘要
- 近期错题摘要
- 用户选段上下文

这样做的好处是后续可以更精确地控制：

- 哪类对话吃哪些上下文
- 哪类场景应该减轻上下文干扰
- 哪类模式应更强调证据

### 5.4 教学策略层

在真正生成回答前，设计上适合引入一层“教学策略选择”，决定回答方式是：

- 直接解释
- 先给提示
- 先反问一步
- 先复述用户理解
- 先定位知识点

对于学习型产品来说，这层比单纯继续堆更多上下文更重要。

### 5.5 流式回答层

教学回答非常适合流式输出，因为：

- 用户常常希望立即看到思路
- 长答案可以边读边理解
- 前端可以边生成边组织展示

因此 `POST + SSE` 应继续作为对话主通道。

### 5.6 对话结果沉淀

对话结束后，系统应继续把交互沉淀为：

- 用户提问记录
- 助手回答记录
- 命中的上下文摘要
- 后续可能扩展的学习事件

这使聊天不仅是“即时输出”，也能成为后续画像和复盘的输入。

## 6. 可结合的技术方法

### 6.1 基础 RAG

当前已采用的向量检索是 Interact 的基础能力，后续可以继续围绕它增强：

- top-k 检索
- 相似度阈值
- chunk 粒度优化
- 命中结果去重

### 6.2 混合检索

后续如果仅靠向量检索不够稳，可以考虑混合使用：

- 向量检索
- 关键词检索
- 标题或章节过滤
- 单元或知识点过滤

对教学资料来说，很多问题天然带有明确术语，混合检索往往会比纯向量更稳。

### 6.3 Rerank 与上下文压缩

当材料规模增长后，Interact 可以继续结合：

- reranker
- context compression
- selected context 优先级

目标不是检索更多，而是把真正适合教学的上下文送进最终 prompt。

### 6.4 多模式 Prompt

当前 Prompt 主要还是单一路径，后续很适合按模式拆分，例如：

- 概念解释模板
- 逐步引导模板
- 错题复盘模板
- 精读选段模板
- 学习规划模板

这样可以明显提升回答风格与教学一致性。

### 6.5 图谱辅助对话

除了 chunk 检索外，Interact 后续还可以结合：

- 图谱节点详情
- Teaching Unit
- Theme Tree 位置
- Prereq DAG 邻接关系

这会让系统从“基于段落回答”逐步升级为“基于知识结构辅导”。

### 6.6 工具化交互

后续 Interact 可以自然长出一些工具能力，例如：

- 从证据弹窗进入对话
- 从错题直接进入复盘
- 让对话触发专项练习
- 让对话输出学习计划

这类能力不需要把 Interact 做成“大而全 Agent”，但很适合作为教学工作台的一部分。

---

## 7. 可以继续长出的能力

Interact 后续非常适合扩展以下方向：

- 选段问答与精读
- 苏格拉底式追问
- 错题自动复盘
- 单元级学习导航
- 一问一练的伴读模式
- 基于薄弱点的追问补链
- 对话生成随堂小题
- 对话引用来源卡片
- 讲义摘要与复习提纲生成

这些能力的共同特点是：它们都在增强“教学过程控制”，而不是单纯增强闲聊能力。

---

## 8. 开发关注点

### 8.1 当前前端还没有把选段上下文真正接入主流程

后端 schema 已经支持：

- `selected_context`
- `source_chunk_id`

但前端主流程还没有把 Summary 页、证据弹窗、选段文本和 ChatPage 真正打通。设计上这应被视为 Interact 非常自然的下一层能力。

### 8.2 当前模式层还较薄

现在 Interact 已经有教学倾向，但还没有真正显式区分“讲解、引导、复盘、规划”等模式，因此后续开发时可以优先在策略层做增强。

### 8.3 当前来源展示还不够强

后端已能返回上下文元信息，但前端还没有把这些信息充分转成“可点击、可查看、可回跳”的教学来源展示层。

---

## 9. 总结

Interact 引擎的核心不是聊天，而是教学对话设计。它应长期围绕三件事建设：

- 用资料和知识结构保证回答有根有据
- 用学习者状态保证回答更像辅导而不是百科
- 用模式和来源层保证对话可解释、可持续、可接回闭环

只要这三件事持续增强，Interact 就会成为系统里最直接体现“教学感”的一层。
