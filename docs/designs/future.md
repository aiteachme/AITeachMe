## 1. 总览：LLM 在学习中的结构性优势

LLM 不是每种学习形式都有优势。以下是 LLM **真正擅长**的学习动作：

| LLM 真正擅长的 | 说明 | 传统方式做不到的原因 |
|---------------|------|---------------------|
| **从资料自动生成内容** | 给一份 PDF，自动出闪卡、题目、大纲 | 传统系统需人工出题 |
| **根据上下文即时解释** | 学生划词就能问，AI 结合教材内容回答 | 搜索引擎无法结合当前学习上下文 |
| **苏格拉底式追问** | 不给答案，一步步引导学生自己想出来 | 需要真人教师 |
| **个性化调节难度** | 根据错题和画像，动态生成适合的内容 | 传统题库是固定的 |
| **多角度解释同一概念** | 类比、例子、图示、代码、反例 | 教材只有一种讲法 |
| **批改+解释为什么错** | 不只判对错，还分析错因和思维漏洞 | 传统自动判卷只能判对错 |
| **角色扮演** | AI 扮演面试官/DBA/运维/用户 | 需要真人 |
| **总结和归纳** | 学完一段后自动总结要点和薄弱点 | 需要学生自己做 |

**LLM 不擅长的**：精确计算、代码执行、真实环境操作 → 这些用 **沙箱** 补。

## 2. P0 — 立刻可做

### 2.1 🃏 闪卡 + 间隔重复（Flashcard + Spaced Repetition）

**一句话**：AI 从知识文档自动生成记忆卡片，用遗忘曲线算法安排复习。

**为什么 LLM 有优势**：
- 传统闪卡系统需要人工制作卡片，LLM 可以从任意教材 **自动生成**
- LLM 可以针对学生的错题 **生成变式卡片**（换个问法考同一知识点）
- 复习时不只翻面看答案，LLM 可以 **追问一句** 检验是否真懂

**用户体验**：

```
[卡片正面]  什么是特征值？
[学生点击"翻转"]
[卡片背面]  矩阵 A 的特征值是满足 Av = λv 的标量 λ
[AI 追问]   "如果把 A 换成单位矩阵，特征值是多少？为什么？"
```

**技术实现**：

| 步骤 | 依赖 |
|------|------|
| Digest 从文档提取知识点 → 生成卡片 | `llm.py` + Digest 引擎 |
| 间隔重复算法决定何时复习 | `events.py`（记录复习事件）+ `memory/` |
| 复习时 AI 追问检验 | `teaching.py` → `check_understanding` |
| 复习结果回流画像 | `events.py` → Profile 引擎 |

**间隔重复算法（SM-2 变体）**：

```
下次复习间隔 = 上次间隔 × ease_factor
ease_factor 根据答题表现调整：
  - 答对且快 → ease × 1.3
  - 答对但慢 → ease × 1.0
  - 答错     → ease × 0.6（缩短间隔，加速复习）
```

### 2.2 🗣️ AI 口试 / 答辩模式

**一句话**：AI 连续追问 3-5 个问题，像论文答辩一样层层深入，检验真实理解。

**为什么 LLM 有优势**：
- 传统考试只能考"背诵"——选择题、填空题都可以靠记忆
- 口试/答辩考的是"**你能不能用自己的话解释清楚**"
- LLM 的追问是**动态的**——学生答到哪，追问就到哪，无法提前准备答案
- **ChatGPT 代答也没用**——因为 AI 会根据前面的回答继续追问

**用户体验**：

```
AI: "请解释一下数据库的 ACID 特性。"
学生: "就是原子性、一致性、隔离性、持久性。"
AI: "好的，你说的没错。那请举一个例子说明，如果缺少'隔离性'会出什么问题？"
学生: "就是...两个人同时操作可能冲突？"
AI: "方向对了。能具体描述一个'脏读'的场景吗？"
学生: "呃...事务 A 读到了事务 B 还没提交的数据？"
AI: "非常准确！最后一问：MySQL 的 InnoDB 默认隔离级别是什么？"
```

**技术实现**：

| 步骤 | 依赖 |
|------|------|
| 根据知识点生成首问 | `teaching.py` → `generate_practice` |
| 根据学生回答动态追问 | `llm.py` + `context.py`（注入知识+画像） |
| 判定回答质量 | `checker.py` → `check_with_llm` |
| 按 rubric 评分 | `checker.py` → Rubric |
| 记录结果 | `events.py` + `memory/` |

**Rubric 示例**：

```json
{
  "full_marks": 20,
  "criteria": [
    {"name": "概念准确性", "weight": 0.3, "description": "核心概念是否正确"},
    {"name": "举例能力", "weight": 0.3, "description": "能否用具体例子说明"},
    {"name": "深度理解", "weight": 0.2, "description": "追问下是否还能回答"},
    {"name": "表述清晰", "weight": 0.2, "description": "逻辑是否清楚"}
  ]
}
```

### 2.3 📝 概念填空式学习（Cloze Learning）

**一句话**：把知识点讲解挖空关键部分，学生填写，即时反馈。

**为什么 LLM 有优势**：
- LLM 可以从任意文本 **自动挖空**（选哪里挖空很关键，需要理解内容）
- 返回反馈时不只说"对/错"，还能解释 **为什么这里应该填这个**
- 可以根据学生填错的内容 **推测思维漏洞**

**用户体验**：

```
"HTTP 是一种 _____ 协议，默认使用 _____ 端口。
 HTTPS 相比 HTTP 增加了 _____ 层加密。"

→ 学生填写：应用层、80、SSL/TLS
→ AI：全部正确！补充：严格来说现在主流是 TLS，SSL 已经被弃用了。
```

**技术实现**：

| 步骤 | 依赖 |
|------|------|
| 从知识文档生成填空题 | `llm.py`（LLM 选择挖空位置） |
| 判定答案 | `checker.py` → keywords 策略 |
| 解释反馈 | `teaching.py` → `explain_concept` |

## 3. P1 — 中期扩展

### 3.1 🎭 场景模拟 / 角色扮演

**一句话**：学生扮演某个角色（DBA / 运维 / 产品经理），在模拟场景中解决问题。

**为什么 LLM 有优势**：
- LLM 可以扮演"对面的人"——上司、用户、系统
- 场景是**动态生成**的，每次练习不重复
- 可以根据学生的操作**实时调整场景走向**
- 传统方式需要真人或预制脚本，成本高、灵活性差

**场景示例**：

| 场景 | 学生角色 | AI 角色 | 学什么 |
|------|---------|--------|--------|
| 线上故障排查 | 值班工程师 | 报警系统 + 其他同事 | Linux / Docker / 排障 |
| Code Review | 审查者 | 提交代码的同事 | 代码质量 / 最佳实践 |
| 技术面试 | 候选人 | 面试官 | 算法 / 系统设计 |
| 需求评审 | 产品经理 | 开发团队 + 用户 | 需求分析 / 沟通 |
| 数据泄露应急 | 安全工程师 | 管理层 + 系统日志 | 安全响应 / 合规 |

**技术实现**：

```python
# 场景引擎（未来可加入 core/scenarios.py）
scenario = load_scenario("db_incident")
session = await start_scenario_session(scenario, user_id="u1")

# 学生操作
response = await session.act("我先看一下数据库的慢查询日志")
# AI: "好的，以下是最近 10 分钟的慢查询：..."

response = await session.act("看起来是全表扫描导致的，我加个索引")
# AI: "你确定直接在生产环境加索引吗？会不会锁表？"

grade = session.grade()  # 按 rubric 评分
```

### 3.2 🧩 代码阅读理解

**一句话**：给学生一段代码，让学生分析输出、找 bug、提优化方案。

**为什么 LLM 有优势**：
- LLM 可以从任意代码仓库 **自动生成** 阅读理解题
- 正确答案不是唯一的，LLM 可以 **判定思路是否合理**
- 可以根据学生的编程水平 **调整代码复杂度**

**题目类型**：

| 类型 | 示例 | LLM 判定方式 |
|------|------|-------------|
| 输出预测 | "这段代码的输出是什么？" | 精确匹配 |
| Bug 发现 | "第几行有 bug？为什么？" | LLM 语义判定 |
| 复杂度分析 | "这个算法的时间复杂度是？" | 关键词匹配 |
| 优化建议 | "如何优化这段代码？" | LLM 语义判定 |
| 功能描述 | "用自然语言描述这个函数做了什么" | LLM 语义判定 |

### 3.3 📊 数据分析实验室

**一句话**：给学生数据集 + 分析需求，在沙箱里用 Python/SQL 完成分析。

**为什么 LLM 有优势**：
- LLM 判定"分析是否合理"比判定"代码是否正确"更有价值
- 可以根据学生的分析思路 **实时引导**（不直接给答案）
- 传统系统只能判"输出是否匹配"，LLM 可以判"方法是否合理"

**用户体验**：

```
题目：分析 sales.csv 中各地区的月度销售趋势，找出异常月份。

学生在 Code 沙箱中写 Python：
>>> import pandas as pd
>>> df = pd.read_csv("sales.csv")
>>> monthly = df.groupby(["region", "month"]).sum()
>>> print(monthly)

AI 反馈：你的聚合方向正确！但建议用 .agg() 替代 .sum()，
因为可以同时看均值和总额。另外，试试用 z-score 检测异常月份？
```

### 3.4 🗺️ 知识图谱探索学习

**一句话**：学生在图谱上点击概念节点，AI 即时讲解，按先修关系自动推荐学习顺序。

**为什么 LLM 有优势**：
- 传统知识图谱只是静态展示，LLM 可以**对图谱上的任意节点即时讲解**
- 可以根据学生的掌握状态 **高亮薄弱节点**
- 点到一个不懂的先修概念时，AI 可以**当场做一轮快速讲解**再往下走

## 4. P2 — 远期差异化

### 4.1 📖 AI 讲故事式教学

用叙事方式讲知识。例如讲"操作系统进程调度"时：

> "想象你是一个餐厅经理。现在有 10 桌客人（进程），但只有 3 个厨师（CPU 核心）。
> 你会怎么安排出菜顺序？先做前菜还是先做主菜？—— 这就是 SJF 和 FCFS 的区别。"

**LLM 优势**：动态生成故事，可以根据学生兴趣（比如喜欢游戏、体育）调整类比。

### 4.2 🎮 知识竞赛模式

类似"一站到底"，限时回答一连串问题。节奏快、有紧张感、适合复习阶段。

**LLM 优势**：自动出题、实时判定、连续升级难度。

### 4.3 📝 AI 帮你做学习笔记

学生看文档/上课时，AI 实时生成结构化笔记。学生可以标注"这里不懂"。

**LLM 优势**：从任意内容自动抽取结构化笔记，标注重点/难点。

### 4.4 🔄 错题重练 + 变式题生成

不只是把错题再做一遍，而是 **AI 生成同类型但不同细节的变式题**。

**LLM 优势**：传统题库变式题是预制的，LLM 可以无限生成变式。

### 4.5 👥 协作式学习

两个学生同时在线，AI 分配角色——一个出题一个答题，然后互换。

### 4.6 🏗️ 项目驱动学习（PBL）

给一个完整项目目标（如"搭建一个博客系统"），AI 拆解为步骤，每一步有指导和验证。
结合 sandbox 真实操作。
